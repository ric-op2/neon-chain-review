# NSFから譜面を作る仕様案

2026-09-10 / NEON CHAIN v0.38を対象にした検討。ゲーム本体は変更していません。

## 結論

NSF読み込み → 音の解析 → 自動譜面 → スクロール編集、は実装可能です。ただし、**任意のNSFを無変換で現在のFDSゲームへ入れる保証はできません**。最初は「標準APU・NTSC・DPCMなし」の対応曲をFamiStudio用データへ変換する方式を推奨します。PCで再生できること、変換できること、FDSで動くことはそれぞれ判定します。

## 今回の試作

- `scrolling.html`：音楽再生に追従してノーツが上から下へ移動。下側の固定線が再生位置。停止中はホイールとシークで移動し、クリック配置、ドラッグ移動、削除が可能。
- 左下・左上・真上・右上・右下の5列（各50px）と、左右共通の旋回1列（66px）。方向は選択ノーツの設定で変更。
- EASY/HARDはそれぞれ編集内容を画面内に保持。重複時刻は配置不可。予告は2拍・3拍。保存、Undo、ゲーム同期プレビューは未実装。
- NSFファイル選択はヘッダーのバージョン・曲数・追加音源を確認するだけです。選んだNSFの再生、自動生成、ゲーム出力はまだ接続していません。

## 小規模な変換実験

既存曲 `outputs/neon-chain/music/neon-afterglow.nsf` をFamiStudio 4.5.3で20秒取り込み、テキスト形式とca65形式へ変換できました。コマンドは以下です（作業ディレクトリはプロジェクトルート）。

```powershell
& 'tools/dotnet/dotnet.exe' 'tools/famistudio-4.5.3/FamiStudio.dll' 'outputs/neon-chain/music/neon-afterglow.nsf' famistudio-txt-export 'work/nsf-import-proof.txt' -nsf-import-duration:20 -nsf-import-pattern-length:120
& 'tools/dotnet/dotnet.exe' 'tools/famistudio-4.5.3/FamiStudio.dll' 'work/nsf-import-proof.txt' famistudio-asm-export 'work/nsf-import-proof.s' -famistudio-asm-format:ca65
```

エクスポーター報告は音楽データ758バイト。これは20秒の変換結果であり、再生ドライバーの容量を含みません。曲全体の変換、原曲との音の比較、FDSリンク・実機相当の再生確認、自動譜面生成はこの実験の対象外です。

## 読み込みから出力まで

1. NSFを選び、曲番号・取り込み秒数・ループ終端を設定。単曲は初期選択し、複数曲は選択を求める。対応する追加音源と形式を解析器が検査する。
2. NSFを隔離された音源エミュレーターで再生して、音声とチャンネルごとの発音候補を取得する。処理時間と出力量に上限を設け、キャンセルできるようにする。
3. BPMと拍の開始位置を推定し、信頼度が低いときだけ確認を求める。NSFのPLAY呼び出し間隔はBPMではない。曲番号・開始無音・取り込み長・テンポマップをプロジェクトに保持して同期ずれを防ぐ。
4. 既定でEASY/HARDの下書きを自動生成する。解析完了後、この編集画面を開く。生成前にユーザーが音を全て入力する必要はない。
5. 音楽をゲームの再生形式へ変換。最適化後のサイズ・RAM・音源競合・処理時間・譜面数を検査し、適合した曲だけFDSをビルドする。
6. 原曲と変換曲を比較試聴し、エミュレーターで全曲を通して同期と操作を検査。出力結果と対応外理由を表示する。

## 自動譜面の生成規則

- 主旋律、ベース、打楽器の発音を候補にする。同じ瞬間の音はまとめ、音量変化だけの行やビブラート、細かいアルペジオを全てノーツ化しない。音の出始めの推定には誤りがあるため下書きとして扱う。
- EASYは左右下段を中心に低密度、HARDは5方向へ展開。単純な音高順だけで位置を決めず、連続操作のしやすさとフレーズを考慮する。
- 旋回は区切りを候補に低頻度で配置。予告2拍/3拍分を確保し、直前直後のキューブを間引く。1拍予告と左右同時旋回は生成しない。
- 最小間隔・曲全体のノーツ上限・同時表示数・旋回後の視認時間を制約として使う。検査できない場合は出力を保留し、該当位置を表示する。
- 同じ曲と設定から再現できるよう、解析版・生成版・乱数シード・入力ファイルのハッシュを保存。密度変更の再生成は編集済み譜面を上書きせず別案を作る。

## 現ゲームで必要になる変更

| 項目 | 現在の状態と対応 |
|---|---|
| メモリ | 現ビルドのCODE/RODATA末尾は`$DD9F`、予約領域手前`$DF00`まで352バイト。BSS末尾`$07EC`から`$0800`まで19バイト。曲の差し替えで既存データは置換できるが、最終リンクサイズを毎回検査する必要がある。 |
| NSFコード | 任意NSFのロード位置・ゼロページ・RAM・バンク切替はゲームと共有できる保証がない。自作曲のNSFもロード位置`$F000`で、FDSにそのまま配置する用途ではない。 |
| 音源 | 現曲は標準APU。FDS音源は効果音に使用し、Pulse 2は旋回予告で一時的に使用する。追加音源やDPCMの対応は再生系・効果音設計を含めて別段階で扱う。 |
| 時間 | 現譜面は120 BPM・1拍30フレーム・7200フレーム終端に固定。曲ごとの終端、テンポ、予告時刻をデータ化する。内部の時刻とNTSC実時間の換算を統一する。 |
| 譜面形式 | 現行のイベント添字は8ビットで、3倍参照にも制約がある。生成器の上限（171未満）を守るか、格納形式と参照処理を変更する。現曲は各118イベント。 |

広い範囲のNSFを変換せずに使いたい場合、PC版でNSFエミュレーターとゲームを並行実行する構成が候補です。その場合も対応形式・追加音源は選んだエミュレーターに依存します。

## 根拠

- [NSF仕様（NESdev）](https://www.nesdev.org/wiki/NSF)：ロード位置、INIT/PLAY、バンク情報、地域、追加音源などの構造。
- [FamiStudioのNSF取り込み](https://famistudio.org/doc/import/#nintendo-sound-format)：NSF/NSFeからの取り込みを提供。ただし元の楽器や繰り返し構造は復元されず、未対応の音源操作は欠落しうるため、変換後の比較が必要。
- [FamiStudioのCLI](https://famistudio.org/doc/cmdline/)：曲番号、取り込み秒数、開始フレームの指定と編集用・アセンブリ形式への書き出し。

メモリと譜面上限は本プロジェクトのビルドマップ・ソースの調査に基づきます。
